# 九寨智游 2.0 项目解读

> **Milvus 混合索引迁移说明（2026-10-02）**：当前默认运行路径是
> `RAG_BACKEND=milvus`。Milvus collection 同时包含 `vector`（Dense）和
> `sparse_vector`（原生 BM25 Function），复合问题通过 Multi-Query 分别召回后由
> 应用层 RRF 融合；PostgreSQL 继续承担实体、公告和结构化事实查询，并作为降级路径。
> 执行 `scripts/index_milvus.py` 会删除并重建指定 collection，旧 Dense-only 索引
> 不支持原地升级；该操作不会删除 PostgreSQL 数据。未配置 Embedding API Key 或
> Milvus 不可用时，服务会明确降级到 PostgreSQL，而不是伪造向量结果。
> PostgreSQL 的兼容向量列使用 `halfvec(2560)` 和 `halfvec_cosine_ops`，避免
> pgvector HNSW 的 `vector` 类型 2000 维上限导致初始化失败。

## 1. 项目定位

九寨智游是面向九寨沟景区游客和运营人员的智能服务平台。它不是只回答景点百科的聊天机器人，而是把静态知识、时效性公告、结构化景区事实、路线约束和游客反馈放到同一条可追溯链路中。

本版本的核心交付是：游客可以直接咨询景点、门票、预约、开放状态、设施和路线；涉及实时状态、限流、自然灾害、政策优惠的问题会优先查找带生效时间的官方公告，并在证据不足或冲突时明确提示，不把推测写成事实。

## 2. 端到端流程

```text
Vue 3 / HTTP-SSE
        -> FastAPI Gateway（会话、限流、trace_id）
        -> Intent Router + Entity/Constraint Extraction
        -> Query Planner（保留原问题 Q0，必要时生成属性/规则 Query）
        -> 混合检索：Milvus Dense + BM25/词面 + Entity + Structured/Notice
        -> Weighted RRF + 去重 + 权威性/时效性加权
        -> Evidence Validator（充分性、冲突、过期、是否拒答）
        -> Supervisor
           -> knowledge_agent / route_agent / realtime_agent / feedback_agent
        -> response_agent + grounding checker
        -> 答案、引用、grounding_status、审计轨迹
```

请求按复杂度分级：简单实体和字段查询优先结构化路径；知识型问题使用 BM25/Dense；复合问题启用 Multi-Query；路线和实时决策才启动多 Agent。这样复杂度由业务问题触发，不会让每个简单问题都付出完整编排成本。

## 3. 数据与来源

当前数据集由 40 个景点、37 个设施、47 段路线、104 条问答、292 个可检索文档组成。新增的 4 条时效性公告单独写入 `notices.jsonl` 和 PostgreSQL `notices` 表，并映射为带 `document_kind=notice` 的知识文档：

1. 2026-07-29 官方全域恢复开放公告：7 月 30 日起全域恢复开放，旺季门票 190 元、观光车票 90 元，限量 41000 人次/天；
2. 2026-08-11 官方售罄公告：8 月 12 日预约达到最大承载量，未预约游客不得贸然前往，可候补或改期；
3. 2026-08-11 官方旺淡季承载和预约口径：旺季 41000、淡季 23000 人次/天，售罄即止；
4. 2026-09-02 官方教师节公告：2026 年 9 月 10 日教师本人携 1 名亲友免门票，观光车票另购，需实名预约和证件核验。

每条公告带 `published_at`、`effective_from`、`effective_to`、`status`、`risk_level`、`authority` 和 `source_ids`。过期公告保留用于审计和历史问答，但当前状态查询优先 active 公告。

来源清单在 `data/jiuzhaigou/facts/sources.json`，新增官方来源为 `src_29`、`src_30`。正式数据使用 `official`、`third_party`、`derived`、`derived_simulation` 分层；游客模拟反馈不参与事实回答。

## 4. 检索设计

`backend/app/services/query_planner.py` 负责生成最多 4 个查询：原始问题 Q0、复合问题拆分出的属性 Query，以及涉及开放、预约、门票、承载量等词时的规则 Query。Planner 不引入原问题中不存在的日期、价格和地点。

PostgreSQL 保留结构化事实、实体检索和可回滚的兼容检索；Milvus 同时承载 Dense 向量索引与原生 BM25 Sparse 索引。应用层将 dense、sparse、entity、structured 四类证据进行 RRF 融合。时效性公告先走结构化条件和公告文档召回，再进入冲突检测，避免仅凭 BM25 的词面相似度回答“现在是否开放”。

## 5. Agent 职责

- `knowledge_agent`：景点、设施、票务、规则和官方问答；
- `route_agent`：提取时长、人群、偏好和设施要求，由确定性路线算法计算和校验；
- `realtime_agent`：公告、开放状态、客流和其他实时状态；
- `feedback_agent`：游客反馈分类、候选知识生成和审核闭环；
- `response_agent`：只使用经 Evidence Validator 通过的证据生成回答，并输出引用和不确定性。

所有 Agent 都受步数、工具数、并发、墙钟和重复调用护栏约束。Milvus、PostgreSQL、Redis 或模型不可用时，系统保留降级路径，不能把失败伪装成“已确认事实”。

## 6. 评测集 2.0

原始 121 条基础题仍保留在 `evaluation_questions.jsonl`，用于和历史结果对比。生成器另外输出：

- `evaluation_complex_questions.jsonl`：5 条复合评测题；
- `evaluation_questions_v2.jsonl`：126 条完整评测题。

复合集覆盖：泥石流后开放状态、预约售罄、候补机制、临时优惠、老人儿童路线和高风险拒答。每道复合题支持 `relevant_document_ids`、`graded_relevance`、`required_facts`、`expected_channels`、`risk_level`、`should_abstain` 等标注。

运行方式：

```powershell
python scripts/evaluate_rag.py --input data/jiuzhaigou/evaluation_questions_v2.jsonl --split all --output reports/eval_v2.json
python scripts/evaluate_rag.py --input data/jiuzhaigou/evaluation_questions_v2.jsonl --split baseline --output reports/eval_baseline.json
python scripts/evaluate_rag.py --input data/jiuzhaigou/evaluation_questions_v2.jsonl --split complex --output reports/eval_complex.json
```

评测输出除 Recall、Precision、MRR、nDCG 外，还包含拒答准确率、检索通道命中统计、问题分组和每题详情。没有 PostgreSQL 时生成的是降级报告，不能冒充线上基线。

## 7. 大众可用的运行方式

开发环境：

```powershell
docker compose up -d
python scripts/generate_jiuzhaigou_data.py
python scripts/import_to_postgres.py --dsn "postgresql+psycopg://postgres:123456@localhost:5432/scenic_agent"
uvicorn app.main:app --app-dir backend --host 0.0.0.0 --port 8000
```

生产环境必须设置随机 `JWT_SECRET`、非默认管理员密码、真实数据库密码、明确的 `CORS_ORIGINS`、可用的 LLM/Embedding 服务，并在生成向量后运行 `scripts/index_milvus.py`。前端通过 `/api/v1/chat/stream` 使用 SSE，可直接提供问答、引用、路线推荐和游客反馈入口。

上线前检查：

- `/api/v1/health` 的 database、milvus、agent_mode 和 write_queue；
- 运行 `python -m pytest -q`；
- 跑基础和复杂评测并保存报告；
- 验证官方公告的生效日期、过期状态和冲突提醒；
- 使用 Locust 检查 100 并发下的 P95 和错误率。

## 8. 已知边界

天气、实时客流、预约余票和临时公告必须依赖最新官方或正式实时数据源；当前仓库中的公告是带日期的公开样本，不等于持续在线的官方接口。景点和设施坐标仍为估算值，不可用于导航。教师节等一次性优惠过期后只能作为历史记录，回答当前优惠时必须重新核对 active 公告。
