# 项目介绍（精简版）

## 当前检索实现（2026-10-02）

Milvus 已从可选 Dense 路径升级为主检索索引：每个知识块同时写入 Dense
`vector` 与原生 BM25 `sparse_vector`，应用层将 Dense、BM25、Entity、Structured
四路证据用 RRF 融合。PostgreSQL 仍是事实源和结构化查询入口。重建命令会删除
目标 Milvus collection 后重新建表和建索引，但不会删除 PostgreSQL；请先配置
`EMBEDDING_API_KEY`，再运行 `python scripts/index_milvus.py`。

**项目名称：九寨智游 —— 景区智能问答与运营 Agent 助手**　　核心成员　　20XX.XX - 20XX.XX

**技术栈**：Python、FastAPI、PostgreSQL + pgvector、Milvus、Redis、arq、Vue 3 + Vite、Docker Compose、Locust、LLM / Embedding Compatible API

**项目简介**：面向九寨沟景区的 LLM 智能客服 + 运营后台系统，集成带生效时间的官方公告、Multi-Query 混合 RAG、Supervisor + ReAct 多 Agent 协作与预算护栏、确定性路线规划、游客反馈知识闭环和全链路审计，为游客提供可溯源、不编造的问答与行程服务。

**核心亮点**：

- **混合 RAG 检索**：当前默认使用 Milvus Dense + 原生 BM25 Sparse 双路召回，PostgreSQL 提供 entity / structured / notice 证据并承担故障回退；Multi-Query Planner 对复合问题生成属性与规则 Query，应用层用 RRF（k=60）融合并叠加来源权威权重与有界时效衰减；按标签分组做冲突检测，返回可解释证据评分、grounding 状态和高风险拒答标志。旧 Dense-only collection 已通过破坏性迁移重建为双索引 schema。
- **Multi-Agent 编排**：Supervisor 一次规划、按依赖拓扑批次并行派发，专员内部 ReAct 自主调用工具；步数 / 工具数 / 并发 / 墙钟四道硬预算，重复调用被拦截，单专员成功直通、不付第二次模型调用。
- **确定性路线规划**：LLM 只选参数、不编行程；规则算法按时长贪心取最多 5 站，叠加开放状态、跨年季节闭园、人群适配与设施覆盖校验，校验报告机器可读。
- **写操作安全**：反馈提交不信任模型传入的确认参数，由工具层校验访客真实轮次消息与待确认草稿，未确认绝不落库，写工具幂等去重。
- **知识闭环与异步任务**：游客反馈 → 候选知识 → 管理员审核 → 正式文档 → 异步 embedding；任务先落库再入队列，Redis 故障不丢任务，无 Key 时标记待配置而非伪造向量。
- **可靠性与可观测**：审计写入走有界队列 + 后台线程并配熔断，任务具备持久化重试与死信状态；Redis / 向量库 / LLM 逐级降级，提供 Prometheus-compatible `/api/v1/metrics`；当前完整基础设施自动化回归为 128 passed，无数据库模式为 123 passed、5 skipped，真实吞吐和延迟仍需 staging 压测。

**备选名称**：九寨沟景区智能服务与运营 Agent（与 README 一致）／智游九寨 —— 可溯源景区知识 Agent

**数字出处**：RRF 与权重、冲突检测 → `backend/app/services/rag.py`；评测指标 → `backend/app/services/evaluation.py`、`scripts/evaluate_rag.py`；预算参数 → `backend/app/agents/loop_guard.py`、`core/config.py`；拓扑并行与直通 → `agents/supervisor.py`、`agents/response_agent.py`；5 站与闭园校验 → `services/route_algo.py`；审核闭环与任务状态机 → `tools/feedback.py`、`app/worker.py`；测试与压测 → `128 passed`、`loadtests/locustfile.py`。

**提醒**：仓库已提供 121 条基础集、5 条复杂集和 126 条 v2 完整评测集；没有 PostgreSQL 时脚本只会生成降级零召回报告，不能将其当成线上基线。部署数据库并导入数据后，再生成 `reports/eval_baseline.json` 与 `reports/eval_complex.json`。
